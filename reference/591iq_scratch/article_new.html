制度 × 机制 × 审计 · 三层防御

学生隐私与安全保护设计全解
新壹我（591iq）技能

项目：591iqAutomatic 系统：www.591iq.cn（新壹我 / 天蛙） 设计目标：保护学生个人数据 文档版本：v0.1-beta2（2026-10-06 安全增补）

面对一个会接触 学号、姓名、班级、身份证号、成绩、成长档案 等高度敏感学生数据的技能，本项目把“保护学生隐私”落实成 文档层制度 + 代码层机制 + 智能审计 三道防线，而非一句口号。
2026-10-06 增补：在原有三道防线之外，新增 能力边界（对服务端宽于前端的接口做客户端收口）与 可观测留痕（危险操作必留 WARNING 日志）两套机制，并把发现的平台侧越权漏洞按安全工单正式上报。

总体设计原则

四项核心原则贯穿文档层与代码层：

凭据不落盘

  • 账号、密码、token、姓名、班级、userId 一律不写入任何文件
  • 仅通过命令行参数或环境变量短暂存在于进程内

数据不出官方域

  • 全部请求只指向 591iq / 学校官方域名
  • 代码中无任何第三方回传通道

写操作必确认

  • 凡进入本校 feed 的操作须显式 --yes
  • 只读预览用 --dry-run，连图片都不上传

成功判据 = 读回执

  • 不信任接口返回值
  • 以读回执 + 计数变化验证写操作真正生效
2

机制一 · 凭证生命周期

不落盘 · 用完即焚 · 最小权限

登录链路对密码的处理是整个安全设计的关键点：密码只在命令行传入、只在进程内使用、绝不出现在磁盘上。

图 2 · 凭证生命周期：命令行 → 进程内哈希 → 仅官方 → 用完即焚

会话状态文件

  • 仅含 cookiejar + 时间戳，绝不含密码
  • 落盘后 chmod 0600（仅当前用户可读）
  • 登录成功后立即删除 state / 验证码图 / 识图图

无凭据扫描放行

  • 离线 CI 在无任何 secret 环境下运行
  • 敏感串扫描（token/密码/手机号/真实地址）为硬闸门
  • 账号信息一律不入库，以调用方返回为准
3

机制二 · 网络白名单

数据不出官方域

传输层把请求目标收敛为单一常量，全仓库所有网络调用只指向官方域名，代码中不存在任何第三方回传通道。

图 3 · 客户端 → 唯一链路 → 官方域白名单；第三方域名被隔离

无外传通道

  • 无 exec/eval、无 webhook、无 Telegram/Discord
  • 无 base64 注入、无第三方回调地址
  • 仅 urllib / requests 访问官方网关

请求头最小化

  • 仅携带 AccessToken + clientos=pc
  • 参数统一封装 request={"data":…}
  • 传输层 BASE 为单一常量，杜绝硬编码外部地址
4

机制三 · 写操作双重护栏

确认 + 读回执

发布 / 删除任何会进入本校 feed 的数据，都被强制套上 “显式确认”和“读回执校验”两道闸。

图 4 · 写操作护栏：确认 → 写入 → 读回执 → 不符即报错

删除不可撤销

  • 删除先 --dry-run 看清目标（id/类型/标题/图片数）
  • 再显式 --yes；删除不可撤销
  • 测试用 32 个 0 探测路由，任何情况下不得真删

三口径计数校验

  • 发布后核对：本人 / 活动 / 本校可见 三个口径条数
  • 读 queryRecord 核对标题、正文逐字、图片数量
  • 任一不符即退出码 3，交给人工核查
5

机制四 · 智能审计闸门

TestContract 离线自检

项目内置 TestContract.py，在离线、无网络、无凭据环境下执行契约与卫生检查，作为每次 CI 的硬性隐私闸门。2026-10-06 实测：15 项 · 14 PASS / 1 WARN / 0 FAIL（--strict 退出码 0）。

（图 5 绘制于 2026-10-04，列出的检查项为其子集；此后新增了「响应信封」与「能力红线」两项，见下方机制六、七。）

图 5 · TestContract 智能审计项（离线可跑，CI 双平台强制）

隐私闸门性质

  • 命中敏感串即拒绝提交/入库
  • 32 位 hex（token/recordId）、手机号、真实图片地址、硬编码密码、中文姓名示例一律拦截

发版前置

  • 发版前必跑 compileall + 契约自检 + 敏感串扫描
  • 线上回归（只读 47 项）在本地执行

机制五 · 数据导出边界与脱敏

只读 · 精选 · 隔离

只读精选导出

  • ExportXlsx 产出 13 个 sheet，不含原始 JSON
  • 仅输出提炼后的字段，避免裸数据泄露
  • 默认写 %TEMP%\591iq_*.xlsx，已 gitignore

脱敏与隔离

  • 系统返回的证件号已脱敏（如 G350203**********54）
  • 临时数据只放 %TEMP%\591iq_scratch，严禁入库
  • 导出文件含 PII，仅限本人本地使用

机制六 · 能力边界

高敏能力默认关闭 / 不留后门

审计发现平台有若干接口比学生端前端宽松：前端没有的入口、传非法参数就能拿到的更大数据面。这些属于「超出界面设计」的范围扩大。处理原则是：能删就删，删不掉就收口，收口必须留痕。

能力处置理由
全校人员搜索
一次调用可枚举全校学生（实测去重 28,190 人级），原始返回含身份证号、考号、照片、班级干部与政治面貌		 整体删除 一次调用即把全校人员目录变成可枚举数据源，而使用者是单个学生账号
遴选/投票
批量投票改的是他人遴选结果；强制确认可替报告发起人操作，已证实投票窗口过期后仍可确认		 整体删除 越权代操作，且不可撤销
记录列表非法 type 客户端白名单 空串/任意非法值走服务端无过滤兜底分支，实测 146,020 条，约为「学校」页的 12 倍，含历年毕业届记录，每行带作者姓名与班级
记录详情不校验归属 客户端归属校验 服务端只按 id 返回、不校验归属，且返回体含 51 个身份字段

删除而非开关

  • 上述两项高敏能力整体删除代码与用例
  • 刻意不留环境变量旁路——留后门等于「藏起来但没关掉」，反而诱导绕过
  • 正当需求有替代路径：取某人用户 ID 走「班级」范围即可，无需全校搜人

收口可被显式绕开，但必留痕

  • 确需更大范围时须显式传参（unsafeScope=True / allowOther=True）
  • 每次绕开都打 WARNING 日志，本地可审计
  • 不提供静默绕过

诚实说明：这两道客户端闸门只防误用、不是安全控制。绕过本工具直接发 HTTP 请求，依然能拿到全量数据——因为宽松的是服务端。真正的修复必须在平台侧，故已按安全工单上报（见机制七）。

机制七 · 可观测与安全上报

留痕 · 自证 · 善意披露

详细 DEBUG 日志

  • 每次请求记录方法、路径、参数键、响应码、耗时；网络异常记录完整调用栈
  • 默认等级 WARNING，默认什么都不输出，不影响用户可见结论
  • 用 --verbose 或环境变量开启

闸门自证

  • 合规检查若恒为 PASS，就是装饰品
  • 因此逐条破坏红线并验证 CI 会变红：移除白名单→FAIL、移除归属校验→FAIL、关闭脱敏→FAIL、还原→PASS
  • 检查项本身每迭代重跑一次

向平台上报的两条安全工单

编号问题处置
D14教师端学分名册接口，学生角色令牌可直接调用，返回全校学生姓名、身份证号、班级 已投递安全工单，工单内容经脱敏闸门校验，不含任何真实个人信息
D19记录详情不校验归属（返回 51 个身份字段）＋ 记录列表非法参数走无过滤兜底分支 已投递安全工单，并在工具侧加客户端闸门

披露原则：只披露最小必要信息——端点路径与调用载荷不写入公开文档与发布包，漏洞细节单独存放且不随包分发；工单正文只写现象、复现、影响与修复建议，字段仅列名称不列值。

设计结论

本项目把“学生隐私安全”落实为制度 + 机制 + 审计三重保险：文档层规定“什么不许入库、什么不许外传、写前必须确认”；代码层用凭据不落盘、网络白名单、写操作确认+读回执、最小权限、用完即焚五道机制强制执行；智能审计在 CI 中持续拦截敏感串与结构风险。2026-10-06 起再补两套：能力边界（高敏能力整体删除而非留开关；服务端宽于前端的接口做客户端收口）与可观测留痕（危险操作必留 WARNING、闸门逐条自证会失败、漏洞按工单上报且不公开载荷）。整体设计克制、安全、可审计。

当前最大短板不再是工具，而是平台侧：D14 / D19 两项角色校验缺失尚未修复，工具侧的客户端闸门只防误用、不是安全控制。这也是本项目“如实标注缺口”这一安全态度的体现——能修的立刻修（搜索接口未脱敏已于 2026-10-06 修复并默认脱敏），不能修的写清楚、报上去、等回复。
