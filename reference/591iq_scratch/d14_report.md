# 学生角色可读教师端学分名册接口（越权 / 未授权访问）

## 现象

`GET /apps/credit/query/list_school` 属于教师端「学分系统」，但**学生角色的 AccessToken
可以直接调用**，返回全校学生的 `studentName` + `idNumber` + `className`。

## 复现步骤

1. 用**学生**账号正常登录，拿到 AccessToken
2. `GET https://service.591iq.cn/apps/credit/query/list_school`
   请求头：`AccessToken: <ssoToken>`、`clientos: pc`
3. 响应 `code=0`，返回全校规模的名册（万级），可分页取全量

## 影响

- 任何持有**任意一个学生账号**的人，都能取到全校学生的姓名 + 身份证号 + 班级
- 身份证号属敏感个人信息，被涉及者为**未成年人**；接口无二次校验、无频率限制、
  无单次返回条数上限，一次调用即可拖取全量
- 同族端点（`list_student` 等）行为一致，说明学分模块整体缺少角色校验，
  不像是单点遗漏

## 建议修复

1. 服务端按 token 解析出的**角色**校验：`/apps/credit/**` 只允许教师 / 管理员
2. 未授权角色返回明确的权限错误码，而不是返回数据
3. `idNumber` 等敏感字段按角色脱敏（教师可见全量，学生不可见）
4. 补分页上限与频率限制，避免一次性拖库

## 补充说明

- 该问题在只读自检过程中发现，工具侧**未做任何批量留存**，也未把数据写入仓库
- 同批核查过：数据查询类端点（`/search/search`、`/record/queryRecordList`）请求里
  不含学校标识，租户由 AccessToken 决定，实测不存在跨校读取路径——这部分设计正常
- 上报前已按脱敏要求处理：本工单不含任何真实姓名、学号、身份证号与凭据
