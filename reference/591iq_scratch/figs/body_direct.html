总览

§ 0
这不是一个通用 skill 集合，而是字节 Doubao（豆包）agent_mode 私有工作区的整包快照。它知识密度很高——1 259 个 reference 文件承载了全部业务知识——但工程收口几乎没做：八成的 skill 没有版本号，七成没有依赖声明，69 个 skill 的入口文档里一条 reference 链接都没有，而 23 个在正文里被明确路由到的目标 skill 根本不在包内。

换句话说：这是一份能读但不敢直接装的资产。装进任何非豆包环境，其中约一半的 skill 会因为内部工具（lark-cli、seed_medical_search、present_files、docs +fetch）不可用而直接失效，剩下的一半则会因入口缺导航而永远不会被触发。

本次审计的对象与口径需要先讲清楚。原始文件 3a8ebdab…等2个文件.zip 内含两个内层 zip：一个是 12.4 MB 的 skill 库快照（根目录另附一份与 skill 无关的定时任务契约 CONTRACT.md），另一个是 118 KB 的豆包 bot 会话导出。两者同包，说明来自同一账号的数据导出。本页只审计前者。

族系构成

§ 1

106 个 skill 分属五个族系。前缀即族界，这是整份库里最可靠的一条分类线索——命名与目录结构完全一致，没有例外。

按文件条目数降序。doubao-* 一族独占 59%，但它只贡献了库内体积的 60%；core 族仅 14 个 skill，却占到 30% 的体积——因为 ppt 一个 skill 就带 147 个 Python 文件。

doubao-* 的领域切分

§ 2

67 个 doubao skill 覆盖六个垂类，切分依据是 skill 名与 SKILL.md 正文中的工具约定，而非目录位置——它们全部平铺在 skills/ 一级，彼此没有交叉引用。

「其他」19 个中包含若干非领域型工具：doubao-cron-scheduler、doubao-enterprise-search、doubao-data-analysis、doubao-pc-optimizer、doubao-app-builder、doubao-identity。其中 doubao-pc-optimizer 带 .ps1 与 .sh 脚本，是全库唯一直接操作宿主操作系统的 skill。

随包附带的自动化工作流

§ 5

库根目录另有一份 CONTRACT.md（11 KB，v6 / 2026-10-08），内容与 skill 库无关，是「GitHub + Gitee 仓库每日变化 → 生成 HTML 报告 → 自动发布到 591iq 综合素质评价系统」的定时任务契约。它被打包时误落在了库根目录，不属于任何 skill。

它的八天演进史本身就是一条完整的契约收紧曲线——正文配额从「精简」一路推到约一万字，配图从固定模板改成 AI 自由设计。

10-04

10-06

富文本实测 关键验证

确认 591iq 正文支持 HTML 标签与行内 style；正文契约由「精简」放宽至 500~1 000 字，产出首版「精美版」开发记录。

正文转为 HTML 富文本 + 定制信息图核心流程；引入 ssoToken 缓存复用以跳过验证码。

10-08

配额上调至约一万字 现行 v6

实测 7 093 字去标签 / 17 217 字符发布成功；新增「富文本美观要求」条款，明确禁止朴素列表堆砌；契约外置为权威文件 CONTRACT.md。

契约本身写得很清楚：正文允许 h3/p/b/i/u/font/ul/li/table/tr/td/th/blockquote/hr/code/pre/a 与行内 style，要求品牌色标题、彩色徽章、分组表格（支持 rowspan/colspan）、引用块与分隔线，末尾固定一行提示。本页的视觉规范即取自这两份约定。

处置建议

§ 8

按收益与成本排序。前两项是纯删除动作，10 分钟内可完成且直接减重 6.7 MB。

  1. 清理打包垃圾

    剔除 255 个 .git/ 条目、.pytest_cache/ 5 条、__pycache__/*.pyc 4 条、package-lock.json。此项对内容零风险。

  2. 消除字节级重复

    journal-rank-index.json 抽至共享 assets，保留一份加软链；跨 skill 复制的模板（feishu-doc-template.xml、ppt-deck-template.xml、literature-log-template.csv）与校验脚本一并收敛。合计减重约 6.4 MB。

  3. 补齐入口导航

    优先级最高的内容工作：为 69 个零链接的 SKILL.md 补 references/ 索引表。缺这一步，这个库的知识密度等于零。

  4. 回填 frontmatter

    为 81 个 skill 补 version，为 76 个补 metadata.requires。依赖声明需按实际运行方式核对：ppt / sheet / pdf 至少需声明 Python 3 与关键第三方库。

  5. 收敛命名重叠域

    doubao-medical-literature-* 4 个各自在 SKILL.md 里写了大段互斥判定规则，本可合并为一个 skill + 四个 mode；doubao-product-* 5 个、doubao-contract-* 3 个同理。

  6. 归一 LICENSE

    99 个 skill 无授权声明，需确认内部使用边界，或统一补 Apache-2.0。

  7. 补测试

    仅 7 个 skill 带 tests/。已被验证可复用的范式是 doubao-product-qa/tests/test_skill_regressions.py（49 KB 回归集）与 doubao-book-writer/scripts/tests/ 三个 .mjs 测试。
