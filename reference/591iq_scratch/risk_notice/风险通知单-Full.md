## 一、摘要

在开发针对新壹我（天蛙）综合素质评价系统（www.591iq.cn）的自动化工具并进行自测的过程中，发现**两处仅凭普通学生账号凭据即可调用、且返回范围或敏感程度超出学生端界面设计的检索接口**。

被涉及的数据主体为**在读未成年人**，其中一处可直接返回姓名、班级，以及身份证号、考号、政治面貌、家庭住址、证件照等敏感字段。

本通知**仅陈述风险并附修复建议**，不含任何真实学生信息样本，不含任何访问凭据。

---

## 二、风险定级

| 项目 | 评价 |
|---|---|
| 风险等级 | **高** |
| 影响对象 | 全校在读学生（未成年人）个人信息 |
| 触发条件 | 任意一个**正常取得的学生账号**凭据，无需管理员或教师权限 |
| 可否批量获取 | 可以（无频率限制、无单次返回上限、支持分页取全量） |
| 是否需要认证 | 需要，但学生角色即可 |

---

## 三、问题详述

### 问题一 · 人员检索接口未按角色限制，返回他人敏感身份信息

**端点**

```
GET https://service.591iq.cn/search/search
```

**请求参数**

```json
{"type": "2", "content": "<姓名片段>", "pageRowBounds": {"offset": 0, "limit": 10}}
```

**鉴权**：仅需在请求头携带 `AccessToken`，学生角色凭据即可调用。

**实测情况**

| 操作 | 结果 |
|---|---|
| `content` 填单个汉字（如姓氏） | `totalResult` 即达上千（实测 2324） |
| 分别以多个常用汉字检索、按 `userId` 去重合并 | 可枚举**全校人员规模**（此前实测约 2.8 万人量级） |
| 返回的人员对象字段数 | **约 51 个字段** |

**返回字段中包含的敏感项**（仅列字段名称，不含任何真实值）：

`identityCard`（身份证号）、`idNumber`（证件号）、`unifiedExaminationNumber`（考号）、`birthday`（出生日期）、`politicalStatus`（政治面貌）、`letter`（家庭住址）、`phoneNumber`、`qq`、`enrollmentPicUrl` / `userHeadImage`（证件照）、`cadres`（班级干部）、`seatNum`（座位号）等。

**问题定性**：学生角色本应只能查看与其本人相关的检索结果，实际可获得全校人员的上述字段。检索结果**未随用户权限降级**。

---

### 问题二 · 记录列表接口对非法 `type` 值不校验，静默返回全量数据

**端点**

```
POST https://service.591iq.cn/record/queryRecordList
```

**请求参数**

```json
{"type": "<任意值>", "recordType": "", "labelId": "", "offset": 0, "limit": 10}
```

**鉴权**：同上，学生角色凭据即可调用。

**前端对照**：学生端界面**只有 4 个**范围选项：

| `type` | 界面上的范围名称 |
|---|---|
| `1` | 我的 |
| `2` | 班级 |
| `3` | 学校 |
| `4` | 年段 |

**实测情况**

| `type` 取值 | 前端是否有对应入口 | 返回总条数 |
|---|---|---:|
| `"1"` | 有（我的） | 18 |
| `"2"` | 有（班级） | 281 |
| `"3"` | 有（学校） | 146,020 |
| `"4"` | 有（年段） | 12,139 |
| `""`（空串） | **无** | **146,020** |
| `"0"` | **无** | **146,020** |
| `"5"` | **无** | **146,020** |
| `"9"` | **无** | **146,020** |
| `"abc"`（任意非法值） | **无** | **146,020** |

**问题定性**

1. 对非法 `type` **不返回参数校验错误**，而是静默进入一个**不做任何范围过滤**的兜底分支；
2. 该分支返回的数据量与「学校」范围**同量级**（146,020 条），并包含历年毕业届记录；
3. 该分支**前端无任何对应入口**，属接口层的能力扩大；
4. 返回的每一行均含 `recordContent.userInf`（作者的 `userId` / `userName` / `className` / `schId`），以及一个 32 位十六进制的记录 `id`，可用于后续调取该条记录的详情；
5. 接口**无频率限制、无单次返回条数上限**，可分页取全量。

---

### 附带说明（另有一项，不在本单范围）

记录详情接口 `POST /record/queryRecord` **不校验记录归属**，传入他人的记录 `id` 即返回该条记录的完整内容及作者身份字段。因该项不属于检索接口，本单暂不列入，可按需另附。

---

## 四、影响分析

1. **越权读取未成年人个人信息。** 任意学生账号即可取得全校学生的姓名与班级，以及身份证号、考号、政治面貌、住址、证件照等敏感字段。此类主体为未成年人，属个人敏感信息中风险最高的一档。
2. **可批量、可重复。** 两处接口均无频率限制与返回上限，实际可形成全校规模的个人信息副本。
3. **信任边界被绕过。** 调用方若依赖 `type` 参数做访问范围控制（一个看似合理的假设），非法取值即可使其完全失效。

---

## 五、建议修复方案

### 针对问题一

1. 按 `AccessToken` 解析出的**角色**限定 `type=2` 分支——学生角色不应返回全校人员目录；
2. 若业务确需同名检索，建议**仅返回最小必要字段**（如 `userId`、`userName`、`className`），`identityCard`、`idNumber`、`politicalStatus`、`letter`、照片类字段对非管理员角色一律不返回；
3. 检索结果按当前用户的可见范围过滤，而非返回全量后交由前端处理。

### 针对问题二

1. 对 `type` 做**枚举校验**，非法值返回参数错误（与系统现有 `999997 参数校验失败` 一致即可），**不要静默落入兜底分支**；
2. 确认该兜底分支是否确有必要保留；若无必要，建议直接移除；
3. 返回的每行 `recordContent.userInf` 中，作者信息同样应按角色裁剪。

### 通用建议

1. 为列表类接口补充分页上限与频率限制；
2. 对涉及身份证号、考号的字段增加**按角色的服务端裁剪**，而非仅在前端隐藏。

### 参考实现（我方工具侧已实现的客户端拦截）

我方已在自动化工具中实现对应的客户端拦截，可作为服务端实现的对照：

- `type` **仅放行前端 4 个合法取值**，非法值直接拒绝且不发出请求；
- 记录详情比对返回的作者 ID 与当前登录者，不一致即拒绝；
- 人员/作者身份字段默认收敛为白名单中的最小集合。

⚠️ **请注意：客户端拦截只防误用，不构成安全边界。** 绕过该工具直接发送 HTTP 请求，依然可以取得全量数据。真正的修复必须在服务端完成。

## 附件 A · 两处接口的调用参数与实测数据摘要


本附件供技术复核使用。**全部数据为条数量级与字段名称，不含任何真实个人信息样本。**

---

### A.1 通用调用约定

两个接口位于同一网关：

```
BASE = https://service.591iq.cn
```

请求头：

```
AccessToken: <学生账号登录后取得的凭据>
clientos: pc
Content-Type: application/x-www-form-urlencoded
```

参数封装为单个 `request` 表单字段，形如 `request={"data":{…}}`。

---

### A.2 问题一 · 人员检索

```
GET /search/search
```

**请求**

```
?request={"data":{"type":"2","content":"<单字>","pageRowBounds":{"offset":0,"limit":10}}}
```

**响应结构**

```
{"totalResult": <命中总数>, "data": null, "list": [ …人员对象… ]}
```

**实测**

| 步骤 | 结果 |
|---|---|
| `content` = 单个汉字 | `totalResult` = 2324 |
| 多个常用汉字分别检索、按 `userId` 去重合并 | 全校人员规模（约 2.8 万人量级） |
| 分页 | 正常生效，可逐页取全量 |

**人员对象字段（约 51 个）**

分为三类：

1. **身份标识类**：`identityCard`、`idNumber`、`identityCardType`、`birthday`、`nationality`、`unifiedExaminationNumber`（考号）、`studentCode`、`individuationUname`
2. **联系方式与住址类**：`phoneNumber`、`qq`、`letter`（家庭住址）、`enrollmentPicUrl`
3. **其他**：`politicalStatus`（政治面貌）、`cadres`（班级干部）、`seatNum`、`headImg` / `userHeadImage`、`gradeName`、`className`、`status`、`schId` 等

> 说明：字段数为在记录详情接口的人员对象上实测所得（51 个）；人员检索接口的返回对象字段集与之高度一致。

---

### A.3 问题二 · 记录列表的范围参数

```
POST /record/queryRecordList
```

**请求体**

```
request={"data":{"type":"<任意值>","recordType":"","labelId":"","offset":0,"limit":10}}
```

**响应结构**

```
{"code": 0, "msg": "操作成功", "data": {"list": {"count": <总数>, "list": [ …记录行… ]}}}
```

**实测矩阵**

| `type` | 前端入口 | `count` |
|---|---|---:|
| `1` | 我的 | 18 |
| `2` | 班级 | 281 |
| `3` | 学校 | 146,020 |
| `4` | 年段 | 12,139 |
| `""` | 无 | 146,020 |
| `0` | 无 | 146,020 |
| `5` | 无 | 146,020 |
| `9` | 无 | 146,020 |
| `abc` | 无 | 146,020 |

**要点**

1. 非法取值**不返回参数错误**，`code` 仍为 `0`；
2. 兜底分支与「学校」范围（`type=3`）返回量级**相同**，均为 146,020 条；
3. 兜底分支包含历年毕业届记录；
4. 每行的 `recordContent.userInf` 含作者 `userId` / `userName` / `className` / `schId`；
5. 每行的 `recordContent.id` 为 32 位十六进制，可用于调取详情；
6. `offset` 分页正常，无频率限制、无单次返回上限。

---

### A.4 前端定义（作为「合法取值」的依据）

学生端界面对 `type` 的定义共 4 项，取自前端组件：

```
[{"id":"2","name":"班级"}, {"id":"4","name":"年段"}, {"id":"3","name":"学校"}, {"id":"1","name":"我的"}]
```

默认值为 `"2"`（班级）。**除这 4 个之外，取值集合中不存在任何其他界面入口。**

---

### A.5 复现所需的最小步骤

```bash
# 1. 以学生账号正常登录，取得凭据（略）

# 2. 问题一：人员检索
curl "https://service.591iq.cn/search/search?request={\"data\":{\"type\":\"2\",\"content\":\"X\",\"pageRowBounds\":{\"offset\":0,\"limit\":10}}}" \
     -H "AccessToken: <凭据>" -H "clientos: pc"

# 3. 问题二：非法 type
curl "https://service.591iq.cn/record/queryRecordList" \
     -H "AccessToken: <凭据>" -H "clientos: pc" \
     -H "Content-Type: application/x-www-form-urlencoded" \
     --data-urlencode 'request={"data":{"type":"","recordType":"","labelId":"","offset":0,"limit":10}}'
```

> 上述命令中的 `<凭据>` 为占位符。**本附件不含任何真实凭据。**

### A.6 我方工具侧的拦截实现（供对照）

**范围白名单**

```
仅放行 type ∈ { "1", "2", "3", "4" }
其余取值 → 直接拒绝，不发出请求
需显式绕开时必须传参，且每次绕开记录 WARNING 日志
```

**详情归属校验**

```
调取记录详情后，比对返回的 userInf.userId 与当前登录者
不一致 → 拒绝
需读他人记录时必须显式传参，且记录 WARNING 日志
```

**身份字段默认收敛**

```
人员/作者对象默认只返回 10 个最小必要字段
```

⚠️ 上述均为**客户端**措施，绕过工具直接发送请求不受限制。
