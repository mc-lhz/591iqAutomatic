## 二、问题一 · 人员检索接口未按角色限制，返回他人敏感身份信息

### 2.1 端点

```
GET https://service.591iq.cn/search/search
```

### 2.2 请求参数

```
request={"data":{"type":"2","content":"<关键词>","pageRowBounds":{"offset":0,"limit":10}}}
```

| 参数 | 说明 |
|---|---|
| `type` | 取 `"2"` 时进入人员检索分支 |
| `content` | 关键字，服务端为**子串匹配** |
| `pageRowBounds` | 分页 `{offset, limit}` |

**鉴权**：请求头 `AccessToken: <ssoToken>`、`clientos: pc`。**凭据验证已通过**——只带头部即可调用，无二次校验。

### 2.3 前端对照

学生端界面**本身提供**该入口（搜索框）。前端全站仅 1 处调用此端点，参数即上述三项。

### 2.4 实测情况

| 操作 | 结果 |
|---|---|
| `content` 填单个常见汉字 | `totalResult` 即达上千（实测 **2,324**） |
| 分别以多个常用汉字检索、按 `userId` 去重合并 | 可枚举**全校人员规模**（实测 **28,190** 人） |
| `limit=50` 硬编码上限，无更高页上限 | 分页可取全量 |
| 返回对象字段数 | **约 51 个** |

> 注：早期口径「人口 34,624」有误。`content` 为子串匹配，各姓 `totalResult` 相交会重复计数，去重后为 28,190。

### 2.5 返回字段（敏感部分）

**① 身份标识类**
`identityCard`、`idNumber`、`identityCardType`、`birthday`、`nationality`、`unifiedExaminationNumber`（考号）、`studentCode`、`individuationUname`

**② 联系方式与住址类**
`phoneNumber`、`qq`、`letter`（家庭住址）、`enrollmentPicUrl`

**③ 其他**
`politicalStatus`（政治面貌）、`cadres`（班级干部）、`seatNum`、`headImg` / `userHeadImage`

> 字段数在记录详情接口的人员对象上实测所得（51 个）；本端点返回对象字段集与之高度一致。
> **上述字段未脱敏**，身份证号为完整明文。

### 2.6 问题定性

学生角色本应只可查看与本人相关的检索结果，实际可获得全校人员的上述字段。**检索结果未随用户权限降级**。

### 2.7 复现步骤（纯浏览器，无需脚本）

```
1. 浏览器正常登录新壹我
2. 在站内搜索框输入一个同学姓名
3. F12 → 网络面板，找到新发出的搜索请求
4. 点击「响应」选项卡，即可看到返回的敏感个人信息
```

### 2.8 命令行复现（供技术方核对）

```bash
curl "https://service.591iq.cn/search/search?request={\"data\":{\"type\":\"2\",\"content\":\"X\",\"pageRowBounds\":{\"offset\":0,\"limit\":10}}}" \
     -H "AccessToken: <凭据>" -H "clientes: pc"
```

> `<凭据>` 为占位符。**本文不含任何真实凭据。**

## 三、问题二 · 记录列表接口范围参数缺少校验

### 3.1 端点

```
POST https://service.591iq.cn/record/queryRecordList
```

### 3.2 请求参数

```
request={"data":{"type":"<任意值>","recordType":"","labelId":"","offset":0,"limit":10,"userName":""}}
```

> payload 前 5 字段必须齐全，否则请求挂起超时。

### 3.3 前端定义（合法取值依据）

学生端界面对 `type` 的定义共 4 项，取自前端组件 `modules` 数组：

```json
[{"id":"2","name":"班级"},{"id":"4","name":"年段"},{"id":"3","name":"学校"},{"id":"1","name":"我的"}]
```

**默认值为 `"2"`。除这 4 个之外，界面无任何其他入口。**

### 3.4 实测矩阵（2026-10-06，`limit=1`，不分页）

| `type` | 前端入口 | `count` |
|---|---|---:|
| `"1"` | 我的 | 18 |
| `"2"` | 班级（默认） | 281 |
| `"4"` | 年段 | 12,139 |
| `"3"` | 学校 | 146,021 |
| `""` | **无** | **146,021** |
| `"0"` | **无** | **146,021** |
| `"5"` | **无** | **146,021** |
| `"9"` | **无** | **146,021** |
| `"abc"` | **无** | **146,021** |

响应 `code` 始终为 `0`、`msg` 为「操作成功」，**不返回参数校验错误**。

### 3.5 问题定性（四条）

1. 对非法 `type` **不返回参数校验错误**，静默进入一个**不做任何范围过滤**的兜底分支；
2. 兜底分支与「学校」tab（`type=3`）**是同一数据集**——`count` 完全相等（倍数 **1.00**），首条记录 id 摘要一致。数字（`0`）与任意字符串（`abc`）均落入该分支，**说明不是解析失败兜底，而是缺少 `type` 校验**；
3. 该分支**含历年毕业届记录**，而界面上的 4 个选项**没有任何一个会返回毕业届数据**；
4. 接口**无频率限制、无单次返回上限**，分页正常，可取全量。

### 3.6 口径澄清：列表本身不返回身份字段

**这一点需特别说明，以免处置方向偏差。** 实测四个 `type` 的返回行中，**`userInf` 字段数均为 0**——列表不返回身份证号、考号等身份信息。

行的 `recordContent` 为 20 个字段：

```
classId, comments, content, createTime, favours, gradeId, id, images,
isDelete, isEdit, labelId, labelName, recordType, schId,
semesterCode, semesterCodeDesc, semesterId, updateTime, userId, userName
```

与个人相关的仅 `userId`、`userName`，班级为**数字 `classId`**（不含班级名称）。

### 3.7 但列表仍构成敏感信息的钥匙链 ⚠️

```
queryRecordList（不校验 type）→ 146,021 个记录 id
        ↓
queryRecord（POST /record/queryRecord，不校验记录归属）
        ↓
该条记录完整内容 + userInf 51 字段
（含 identityCard / idNumber / unifiedExaminationNumber 考号 /
  politicalStatus 政治面貌 / letter 住址 / enrollmentPicUrl / userHeadImage）
```

**风险实际落在第二跳。** 但本接口的价值在于：它以一次分页铺满的方式提供了 14 万个 id，成本远低于问题一那种「多关键字枚举拼接」。

### 3.8 命令行复现

```bash
curl "https://service.591iq.cn/record/queryRecordList" \
     -H "AccessToken: <凭据>" -H "clientes: pc" \
     -H "Content-Type: application/x-www-form-urlencoded" \
     --data-urlencode 'request={"data":{"type":"","recordType":"","labelId":"","offset":0,"limit":10,"userName":""}}'

# 建议的四次对比：type 分别取 "1" / "2" / "3" / "0"，观察 count
```

## 四、影响分析

| 项 | 结论 |
|---|---|
| 影响对象 | **全校在读学生（含未成年人）**个人信息 |
| 触发条件 | 任意一个**正常取得的学生账号**凭据，无需管理员或教师权限 |
| 泄露内容 | 身份证号、考号、政治面貌、家庭住址、证件照等**个人敏感信息** |
| 可否批量 | **可以**——无频率限制、无单次返回上限、分页正常 |
| 是否需要认证 | 需要，但学生角色即可 |
| 可持续性 | `ssoToken` 在有效期内可重复使用 |

**法律层面**：《中华人民共和国个人信息保护法》规定**不满十四周岁未成年人的个人信息属敏感信息**，要求信息处理者制定专门处理规则，确保处理活动的合法性、正当性、必要性。本漏洞使「必要性」与「权限最小化」两项要求均无法成立。

**横向影响面**：该平台为**每校独立部署的多租户**架构。经核，数据查询类端点的请求中**不含任何学校标识**，租户完全由 `AccessToken` 决定。因此**同一缺陷很可能在其余各校部署中同样存在**——我方仅验证了本校部署，其余学校是否受影响需由平台方自查。

> ⚠️ 我方仅能确认「缺陷位于共用代码路径」，**不能代其他学校断言受影响**，该结论请平台方以自身部署记录为准。

## 五、修复建议

### 5.1 针对问题一

1. `/search/search` 按 `AccessToken` 解析出的**角色**限定分支——学生角色不应返回全校人员目录；
2. 人员对象的返回字段**按角色裁剪**：学生角色不应下发 `identityCard` / `idNumber` / `unifiedExaminationNumber` / `letter` / `politicalStatus` / `enrollmentPicUrl` / `userHeadImage`；
3. **移除前端搜索入口**，或将其限定为「仅搜索本人」；
4. 补频率限制与分页上限。

### 5.2 针对问题二

1. **白名单校验**：`type` 不在 `{1,2,3,4}` → 直接返回参数错误，**移除 `else` 兜底分支**；
2. **按角色收紧**：`type=3`（学校）对学生不应开放至全校范围，应受班主任/年级权限约束；
3. **清理毕业届**：学生端任何范围均应排除已毕业记录；
4. 补速率限制与分页上限。

### 5.3 通用

1. `POST /record/queryRecord` **补归属校验**——校验记录是否属于当前用户可见范围；
2. **不要把客户端输入当控制指令用**。范围控制的判断必须在服务端独立完成，不能依赖「前端只提供 4 个选项」这一假设；
3. 建立 `ssoToken` 的使用审计与异常访问告警。

## 六、我方已采取的自我约束

| 措施 | 实现 |
|---|---|
| 停止使用相关功能 | 问题一能力**代码整体删除**（`SearchQuery` 仅保留记录全文搜索） |
| 删除投票/遴选域 | 写操作会改**他人**遴选结果或替发起人强制确认，属越权代操作，整域移除 |
| 范围参数白名单 | 仅放行 `{1,2,3,4}`，其余抛错且**请求不发出**；旁路须显式传参并留 WARNING |
| 归属校验 | 读记录详情时比对 `userInf.userId`，不符即拒；旁路须显式传参并留 WARNING |
| 默认脱敏 | `userInf` 由 51 字段收敛至 10 字段白名单（保留 userId / userName / className 等），**默认即脱敏** |
| 反馈工单闸门 | 投递前扫描 payload，命中身份证号、学号、手机号、姓名等即**拒发** |
| 提交前扫描 | CI 扫描仓库，命中 token / 手机号 / 密码 / 真实图片地址即失败 |
| 回归防护 | CI 每次校验上述红线，危险能力被加回即拦截 |
| 凭据管理 | 账号、token、导出文件一律不入库 |

> ⚠️ **重要声明**：以上均为**客户端措施，仅防止误用，不构成安全控制。**
> 绕过本工具直接发起 HTTP 请求，仍可获得全量数据。**平台侧缺陷必须由平台方修复。**

## 附件 A · 补充说明

### A.1 count 会漂移，请勿作为断言

| 日期 | `type=3` / 非法值 `count` |
|---|---:|
| 2026-10-05 | 146,020 |
| 2026-10-06 | 146,021 |

`count` 随记录增长变化。**判定分支归属应比对记录 id，不应比对 count**——10-05 快照与 10-06 实测相差 1 条，两组数字均可自洽。

### A.2 我方工具侧的拦截实现（供对照）

```
范围白名单：仅放行 type ∈ {"1","2","3","4"}
            其余取值 → 直接拒绝，不发出请求

归属校验：  queryRecord 返回后比对 userInf.userId
            与当前登录者，不符即拒

默认脱敏：  userInf 收敛到 10 字段白名单
            userId / userName / userNameAndClassName / className /
            gradeName / enrolYearName / sex / status / schId / userType

旁路要求：  unsafeScope=True（范围）、allowOther=True（归属）
            两者均打 WARNING 留痕，不提供静默绕过
```
