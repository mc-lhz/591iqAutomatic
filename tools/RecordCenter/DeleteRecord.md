# DeleteRecord（写实记录删除·命令行）

删除一条已发布的写实记录。**删除不可撤销**，所以本模块的立场是「默认只读」：
不给 `--yes` 绝不删，`--dry-run` 只把要删的那条打出来（id / 类型 / 槽位 / 标题 /
学期 / 图片数 / 正文字数），让人先看清目标。

库能力在同目录 `RecordWrite.py`（`deleteRecord`）；本文件只做参数校验、
目标展示与删除后的回执校验。

## 为什么有这个模块

2026-10-04 之前，本仓库所有文档都写着「学生端未发现删除接口，提交后无法自行撤销」——
**这是错的**。错因是只 grep 了 `deleteRecord`：项目里删除类端点一律用 `del` 前缀
（`delSummary` / `delComment` / `reviewDel`），所以记录删除叫 `delRecord`。

影响不只是「多一个功能」，而是**风险定性变了**：从「撤不回来」变成「能撤」，
于是「提交前必须向用户确认」这条规矩从「没办法只能这样」变成「仍然要这样做」。

## 对应端点

- `POST /record/delRecord` — 删除
- `POST /record/queryRecordList`、`POST /record/queryRecord` — 删除前后回执校验

## 用法

```bash
cd <仓库根>

# 先看要删的是哪一条（不写入）
python tools/RecordCenter/DeleteRecord.py --id <recordId> --dry-run

# 确认无误后再删（必须显式 --yes，代表已向用户核对）
python tools/RecordCenter/DeleteRecord.py --id <recordId> --yes
```

token 优先级：`--token` > 环境变量 `IQ_SSO_TOKEN` > `-u/-p`（内部走 `LoginToken.loginForToken`）。

## 参数

| 参数 | 说明 |
|---|---|
| `--id` | 必填。要删的 `recordId`，**32 位十六进制**（`queryRecord` 返回的那个）；位数或字符不对直接退出码 5，不发请求 |
| `--dry-run` | 只打印目标与当前条数，不删除 |
| `--yes` | 确认已向用户核对后才允许删 |

## 回执校验做了什么

1. 删除前取条数快照：本人记录数 / 本校可见记录数。
2. `queryRecord(id)` 展示目标详情；**查不到就拒绝发请求**（避免拿一个错的 id 去删）。
3. 核对槽位名：`RECORD_TYPE_MAP[recordType]` 与详情里实际存在的槽位是否一致。
4. 删除后再取快照：要求**本人记录数恰好 −1**、本校可见记录数**不增**。
5. 再 `queryRecord(id)`：必须查不到。
6. 任一项不符 → 退出码 3 并打印 `!!` 明细。

## 退出码

| 码 | 含义 |
|---|---|
| 0 | 删除成功且回执一致（或 `--dry-run` 正常结束） |
| 2 | 服务端拒绝 / 请求异常；含路由 404（→ 接口可能已下线，需同步改文档） |
| 3 | 回执校验不一致：接口说成功但记录还在 |
| 4 | 缺 token / 登录失效 |
| 5 | 前置校验失败：缺 `--yes`、id 不是 32 位十六进制、id 查不到 |
| 6 | 其他未预期异常 |

## 注意事项

- **删除不可撤销**，执行前必须先 `--dry-run` 看目标，并取得用户同意。
- 目前**没有**批量删除、按条件删除；一次一条，删错就要重新填。
- 只验证过「路由存在且对不存在的 id 返回业务错误」；**是否只能删自己的、能否删
  已审核通过的记录，均未验证**——删别人的记录前请自行确认。
- `TestApiReadOnly.py` 里有一条常驻用例 `record/delRecord (仅探测路由，不删)`，
  用 32 个 `0` 探测路由是否还在（404 → FAIL）。**它永远不会删任何东西**，
  真删只走本模块。
- 接口契约与验证记录见 `reference/api.md`「删除写实记录」一节；issue #1 是发现来源。
